## 5. 사용자 관점 피드백

### 5-1. 페인 해소
- 영-영 의역 N건 시나리오: **클릭 수 3N → 3**
  - 단건: ⓧ × N + 라디오 × N + 확인 × N
  - 일괄: 일괄 버튼 1 + 라디오 1 + 확인 1
- 사유 모달 UI 가 단건과 동일 → 학습 비용 0
- 의역만이 아닌 4 메인 카테고리 모두 동일 패턴 — 일관성 있음

### 5-2. 안전 인식
- "N건 제외" 라벨이 모달 Primary 버튼에 박혀있어 적용 결과 명확
- 5초 [↺ 전체 복원] 으로 실수 복구 보장 → 클릭 부담 감소

### 5-3. 잠재 우려 (수용 가능 수준)
- N=1 인 그룹에서도 일괄 버튼 노출 — 단건 ⓧ 와 기능 중복. 다만 사용자가 "그룹 통째로 정리한다" 의도가 분명한 워크플로우라 보존이 일관성 측면에서 유리

## 6. 웹디자인 전문가 관점 피드백

### 6-1. 시각 통일성 ✅
- 버튼 디자인은 헤더 컨텍스트에 종속적 (헤더 톤과 동일 hierarchy)
- 호버 시 빨강(파괴 액션 신호) — 카드 ⓧ 와 동일 의미 매핑
- 다크 모드: `--text-light` 회색 위 빨강 호버, 충분한 콘트라스트
- 라이트 모드: 동일 토큰, 콘트라스트 보존

### 6-2. 정보 위계
- 헤더 좌→우: 컬러바 → 라벨 → 카운트 → **액션 버튼**
- 액션은 가장 우측 — 사용자 시선 종착지에 배치 (F-패턴 부합)
- 헤더 sticky 제거 상태 (Plan-45 P3.6) 와도 충돌 없음

### 6-3. 접근성
- aria-label, title, focus-visible outline 모두 적용
- 키보드 Tab 순서: 헤더 라벨 → 카운트 → 일괄 버튼 → 첫 카드 — 자연스러운 순서

### 6-4. 개선 제안 (수용은 후속 판단)
1. **그룹 비워진 후 시각 잔향 부족**
   - 일괄 제외 후 헤더 자체가 사라짐 → 사용자가 "방금 어디 있었지" 감각 약함
   - 향후 옵션: 제외 패널 헤더에 "최근 일괄: 의역 N건" 미니 라벨 5초 표시
2. **버튼 텍스트 길이 (최소 폭 보존)**
   - 다크 모드 좁은 사이드바 (~280px) 에서 카운트 배지 + 버튼 텍스트 줄바꿈 가능
   - 현재는 카드 패널 폭이 좀 더 넓어 문제 없으나, 향후 사이드바 리사이저 도입 시 `white-space: nowrap` 필요할 수 있음
3. **버튼 텍스트 짧은 형태도 검토**
   - "일괄 제외" → 아이콘만 + tooltip 으로 미니멀화 가능
   - 다만 "사용자가 처음 봤을 때 발견 가능성" 측면에서 현재 형태 유지가 안전 — 후속 사용자 관찰 후 결정 권장
