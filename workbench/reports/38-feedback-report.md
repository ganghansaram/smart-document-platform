## 1. 강점 (User·UX 관점)

### 1.1 정보 계층화가 명확함 — "원하는 정보를 빠르게 찾는다"
- **점수 카드 (1차)**: 큰 % + verdict 라벨 — 결론을 즉시 본다
- **4그룹 누적 바 (2차)**: 표절 의심/참고/제외/일반 한눈에
- **검사 설정 패널 (3차, 접이식)**: 평소엔 접힘, 필요할 때만 펼침
- **매칭 카드 (4차)**: 개별 항목 검토
- **모달 A/B/C (5차)**: ⓘ 클릭 시 깊이 있는 학습

→ Turnitin/iThenticate의 "Insight Panel" 패턴과 동일하지만 **한국 사용자 친숙한 카피킬러식 4그룹**으로 표시.

### 1.2 SSOT 단일 소스가 만든 일관성
모달 A/B/C, 보고서 부록(L4), 가이드 페이지(L3), 툴팁(L1) 모두 `data/help/similarity-help.json` 한 곳에서 파생. 사용자가 어디서 보든 **동일한 산식·라벨 정의·면책**을 만남. 향후 임계값 갱신 시 한 곳만 수정.

### 1.3 "왜?"를 적극적으로 알려주는 도움말 체계
- 점수 옆 ⓘ → 산식·5단계 신호등 (왜 이 점수?)
- 4그룹 옆 ⓘ → 2축 다이어그램 + 6라벨 표 (왜 이 라벨?)
- 검사설정 옆 ⓘ → 7옵션 가이드 (왜 이 옵션?)
- 면책 명시 ("유사도 ≠ 표절") — 잘못된 사용 방지

→ 사용자의 가장 큰 의문 ("이게 뭐야?") 모든 영역에서 즉시 해결.

### 1.4 인쇄 보고서가 회람용으로 우수
- A4 자동 분할 + 부록 마지막 페이지 별첨
- 출처 번호 마커 `[1]` — **흑백 인쇄에서도 본문↔출처 추적 가능**
- 검사 기준 자동 첨부 — 받는 사람이 도구 몰라도 즉시 이해
- 결재선·보안등급 없는 산업 표준 양식 (Turnitin/iThenticate 방식)

### 1.5 검사 설정의 "즉시 재계산" UX
백엔드 재요청 없이 프론트만으로 점수·breakdown·매칭 흐림 효과 즉시 적용. 사용자가 "참고문헌 제외 켜면 어떻게 되지?" 같은 실험을 부담 없이 가능.

### 1.6 1회 자동 온보딩의 가치
신규 사용자가 처음 진입 시 자동으로 3-step 학습. 익숙해진 후엔 ❓로 재실행 가능. **학습 비용 매우 낮음**.

## 2. 발견된 이슈

### 🟡 Issue #1: 사이드바 4그룹 라벨 가독성 부족 (Medium)
**증상**: "표절 의심 70참고 가능 3제외 영역 17일반 10ⓘ" — 라벨 사이 공백이 좁아 한 줄로 다닥다닥 붙어 보임.

**원인**: `.sim-group-label` 의 `gap` 또는 `margin` 부족. 현재 `gap: 4px`인데 라이트 모드 + 좁은 사이드바에서 부족해 보임.

**영향**: 첫인상에서 시각적 노이즈. 정보는 정확하나 분리감 부족.

**개선 권고**:
```css
.sim-group-labels { gap: var(--space-md); }  /* 4px → 12px */
.sim-group-label { padding: 2px 0; }
```
또는 라벨을 2x2 그리드로 배치.

### 🟡 Issue #2: 모달 A 크기 vs 사이드바 폭 (Low)
**증상**: 모달 A (720px) 가 사이드바를 일부 가림. 사이드바가 좁아 모달이 거의 전체 화면 차지.

**원인**: 모달 박스 720px이 SVG 가독성을 위한 최소치인데, 작은 화면에선 viewport 대비 큼.

**영향**: 모달 사용 중 사이드바 결과를 동시에 볼 수 없음 (참조 어려움).

**개선 권고**:
- 옵션 A: 모달을 사이드바 옆 패널로 변경 (영구 dock)
- 옵션 B: 모달 크기 축소 + SVG를 collapsible accordion으로
- 옵션 C: 현 상태 유지 (도움말은 일회성 학습이므로 큰 문제 X)

### 🟡 Issue #3: 온보딩 자동 노출 타이밍 (Low)
**증상**: 모드 진입 즉시 (400ms 지연) 온보딩 모달이 뜸. 사용자가 아직 화면을 보기도 전에 모달이 가림.

**원인**: `setTimeout(showSimOnboarding, 400)` — 400ms는 짧음.

**개선 권고**:
- 사용자 액션 후 노출 (마우스 움직임 또는 1~2초 idle)
- 또는 첫 검사 결과 표시 후 노출 (검사 완료 → 온보딩 → "이게 뭔지 알려드릴까요?")

### 🟢 Issue #4: 보일러플레이트 phrase 303개 → 사용 빈도 분석 필요 (Low, 향후)
**증상**: phrase 사전 303개 중 실제 매칭에 기여하는 phrase가 얼마나 되는지 측정 안 됨.

**개선 권고** (향후): 실 사용 1개월 후 매칭 통계 분석 → 사용 빈도 0인 phrase 정리.

### 🟢 Issue #5: 큰 문서 처리 시간 (Low)
**증상**: 시드 5배(485 문장) 입력 시 20초 소요. 100~200 문장 표준 문서는 5초 내.

**개선 권고** (향후 확장 시):
- L3 임베딩 배치 크기 증가
- 문장 페어 전수 비교 → 후보 선별 (k-NN) 단계 추가

### ✅ Issue #6 (테스트 코드 false positive): /api/settings/public verdict_bands None
**증상**: 초기 테스트에서 `verdict_bands: None` 으로 보였음.

**조사 결과**: API는 `{"frontend": {...}}` 로 래핑되어 반환. compare.html은 `data.frontend`로 정상 사용. **백엔드는 정확하게 동작**. 테스트 코드의 키 접근 오류였음.

## 3. 산출물 품질 (코드 전문가 관점)

### 3.1 아키텍처 분리 우수
- **백엔드**: similarity_engine.py 모놀리식이지만 함수 단위 모듈화 (`_classify_match`, `_detect_boilerplate`, `_detect_exclusions`, `_compute_summary`)
- **API**: help 라우터 분리 (`backend/api/help.py`), 향후 `/help/compare`, `/help/verify` 확장 용이
- **프론트엔드**: 모달 A/B/C 각각 독립 함수, 사이드바 이벤트 위임 패턴

### 3.2 호환성 유지 우수
- 모든 기존 필드 보존 (`high_count`, `medium_count`, `tiers.*`, `breakdown.*`, `level`, `similarity`, `method`)
- 신규 필드는 모두 optional (`verdict`, `sources`, `exclusion_reason`, `exclusion_breakdown`)
- compare/verify 모드 무수정 — 기존 사용자 영향 0

### 3.3 설정 외부화 우수
모든 임계값이 `config.py`에 명시:
- `VERIFY_SIMILARITY_THRESHOLD_HIGH/MEDIUM`
- `VERIFY_SIMILARITY_PARA_FP_MAX/TRANS_FP_MAX`
- `VERIFY_SIMILARITY_CROSS_LANG_SEM_TH` (R1 신규)
- `VERIFY_SIMILARITY_BOILERPLATE_TH` (R1 신규)
- `VERIFY_SIMILARITY_VERDICT_BANDS`
- `VERIFY_SIMILARITY_DEFAULTS` (검사 설정 5옵션)

→ 실 사용 후 사용자별 조정 가능.

### 3.4 측정 인프라 우수
- 골드셋 14페어 + `tools/eval/similarity_eval.py`
- PASS/FAIL 자동 판정 + JSON 출력
- 향후 회귀 발생 즉시 감지 가능

### 3.5 잠재적 개선
| 항목 | 현재 | 개선 권고 |
|---|---|---|
| similarity_engine.py 크기 | 1000+ 라인 (단일 파일) | `_classify`, `_exclusions`, `_summary` 모듈 분리 (향후 1:N 확장 시) |
| compare.html 크기 | 5500+ 라인 (모놀리식) | 향후 `compare-similarity.js` 등 모듈화 (현재는 CLAUDE.md 정책상 OK) |
| 테스트 자동화 | 골드셋 평가 도구만 (수동 실행) | CI 통합 시 PR 시 자동 실행 (향후) |
