## 3. 관점별 피드백

### 🧑‍💻 개발 전문가 — 회귀·가역성: 우수
- **순수 추가**: 기존 `save_document`/`menu.py`/업로드 경로 무수정. 기존 메뉴 동작 회귀 없음(실측).
- **graceful degradation**: `fetchAuthoredDocs()`가 실패 시 `[]` 반환 → 백엔드 다운이어도 `menu.json` 트리는 정상 렌더. 폐쇄망/백엔드 분리 실행 환경에 적합.
- **머지 안전성**: `mergeAuthoredNode`가 원본 불변(얕은 복사) + 기존 `_authored` 제거 후 삽입 → 반복 `loadMenuData`에도 폴더 중복 없음(reload 실측 확인).
- **오염 차단**: `_authored` 가상 노드는 `AppState.menuData`에만 존재. admin 메뉴 편집기는 `GET /api/menu`(static `menu.json`)에서 읽으므로 가상 노드가 `menu.json`에 **저장될 경로 없음**. 깨끗.
- ⚠️ **[W1] 저장 후 갱신 경로 불일치**: 신규 저장 시 `loadMenuData()`를 호출하나, 이는 **트리 전체 재렌더** → 펼침 상태·활성 하이라이트 소실 + 방금 만든 문서를 **하이라이트/오픈하지 않음**. 업로드 경로(`reloadTreeMenuAndLoad`)는 `highlightCurrentPage(outputPath)`로 새 문서를 짚어주는데, 저장 경로는 그 일관성이 빠짐. (모달이 덮고 있어 즉시 체감은 낮으나, 닫은 뒤 "내가 만든 게 어디 있지" 발생 가능)

### 🔧 코드 전문가 — 견고성: 양호, 입력 위생만 보강 여지
- 파서 `_read_front_matter_title`: BOM·따옴표·닫힘 없음 모두 안전 처리, 선두 2048바이트만 읽어 효율적. 정규식이 md-editor `buildFrontMatter` 형식과 일치.
- ⚠️ **[W2] 제목 미검증**: XSS는 프론트 `textContent`로 막히지만, 백엔드는 제목을 **정규화/길이 제한 없이** 그대로 반환. 깨진/HTML/초장문 제목이 라벨로 그대로 노출(예: `<img src=x ...>` 텍스트가 메뉴에 뜸). 방어는 표시단 1겹뿐 — 저장단(`save-markdown`) 또는 표시 길이 캡 1겹 추가가 견고.
- ℹ️ **[I1] 성능**: 메뉴 로드마다 `os.listdir` + 파일당 2KB read, 캐싱 없음. 수십 개는 무영향, **수백 개 누적 시 메뉴 초기 로드 지연** 가능. 디렉토리 mtime 캐시 또는 인덱스 파일로 후순위 최적화 여지.
- ℹ️ **[I2] 정렬 고정**: 수정시각 desc 하드코딩. 이름/작성자 정렬, 페이지네이션 없음(현 규모 OK).

### 🎨 UI/UX 전문가 — 발견성 달성, 식별성은 약점
- **발견성(핵심 목표) 충족**: 홈 바로 아래 고정 = 최상위 가시성. 방법 가의 취지대로 "쓴 글을 바로 찾는다" 동작.
- ⚠️ **[W3] 동명 문서 식별 불가**: 중복 제목 2건이 메뉴에 **완전히 동일한 라벨**로 표시 → 어느 게 어느 것인지 구분 수단 없음(작성자/날짜/파일명 힌트 부재). 실사용에서 "보고서", "회의록" 등 흔한 제목 충돌 빈발 예상. → 라벨 옆 보조정보(작성자·날짜 tooltip 또는 부제) 권고.
- ℹ️ **[I3] 저장 후 피드백 약함**: W1과 연동 — 새 문서가 목록에 "나타나지만" 시선 유도(자동 하이라이트/스크롤)가 없어 생성 성공의 시각 확인이 약함.
- ℹ️ **[I4] 관리 동선 부재**: 메뉴에서 작성 문서 이름변경·삭제·이동 불가(편집·내보내기는 가능). 평면 누적만 됨 — 큐레이션/관리 레이어 미구현(알려진 후속).

### 🖌️ 웹디자인 전문가 — 톤 일관성: 합격
- 라이트/다크 모두 기존 트리와 **완전 동일한 톤**(아이콘·간격·호버). 별도 CSS 0줄로 토큰 자동 상속 — 하드코딩 금지 규칙 위반 없음.
- ℹ️ **[I5] 시각 구분 부재**: "작성 문서"가 큐레이션 폴더와 **같은 폴더 아이콘**. 일관성 측면 장점이나, "사용자 생성/초안" 영역임을 알리는 단서가 없음. 의도된 통일이면 OK, 구분이 필요하면 전용 아이콘(예: 연필/문서더미) 1개 고려.

### 👤 사용자(일반 엔지니어) — 진입장벽 해소
- "새 문서로 쓴 글이 왼쪽 메뉴에 바로 보이고, 누르면 열린다" = 기대 충족. 이전의 "저장하면 사라지는" 미아 문제 해결.
- 모든 사용자(viewer 포함)가 작성 문서 폴더를 보고 열람 — 계획의 전역 공유(v1) 의도와 일치.
- 체감 리스크: 문서가 쌓이면(특히 동명) **목록에서 내 것 찾기**가 어려워질 것(W3·I2·I4의 사용자측 발현).

## 5. 보안·정보노출 메모
- `GET /api/authored` **무인증** — 비로그인 포함 누구나 작성 문서 **제목·파일명 열거** 가능. 콘텐츠가 정적 공개 서빙 + `menu.json`도 공개 파일이라 **현 모델과 일관**, 폐쇄망 저위험. 단 작성 문서가 "초안" 성격을 띠면(미승격 노출) 정책 판단 필요 — 로그인 필수로 좁히려면 `require_login` 1줄 추가로 가능.
