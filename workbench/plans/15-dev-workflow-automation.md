# 개발 워크플로우 자동화 — 실행 계획서

> 작성일: 2026-03-17
> 최종 갱신: 2026-03-17
> 상태: Phase 1 완료 / Phase 2 미착수

---

## 목적

Claude Code의 Hooks, 서브에이전트를 전략적으로 구성하여 개발 사이클의 반복 작업을 자동화하고 품질 게이트를 강화한다.

## 현황 진단

| 영역 | 현재 | 목표 |
|------|------|------|
| **스킬** | 4개 (commit, review-ui, test-backend, update-docs) | 유지 (충분) |
| **에이전트** | 1개 (plan-advisor) | 3개 (+ codebase-researcher, code-reviewer) |
| **훅** | ~~0개~~ 1개 (커밋 전 검사) | 1개 ✅ |
| **워크플로우** | 매 단계 수동 트리거 | 훅 자동 + 에이전트 역할 분리 |

## 핵심 문제

1. **디버그 코드 유출** — console.log, debugger 등이 커밋에 포함될 수 있음
2. **컨텍스트 낭비** — 구현 전 파일 수십 개를 메인 대화에서 읽어 30~40% 소모
3. **코드 리뷰 부재** — 구현 후 품질·보안·패턴 검증이 체계적이지 않음

## 실행 계획

### Phase 1: Hook — 커밋 품질 게이트

> 셸 스크립트로 간단하고 오탐이 적은 검사만 자동화한다.
> CSS 토큰 검사, API 인증 검사 등 복잡한 검증은 기존 스킬(/review-ui)이나 에이전트(code-reviewer)가 담당.

- ✅ **1-1. 커밋 전 디버그 코드 검사 훅**
  - 트리거: `PreToolUse` — Bash로 `git commit` 실행 전
  - 동작: staged 파일에서 `console.log/debug/warn/error/info`, `debugger`, `alert(` 탐지
  - 대상: `.js`, `.html` 파일 (`.min.js` 제외)
  - 실패 시: 커밋 차단 (exit 2) + 발견 항목 리스트 출력
  - 범위: 의도적으로 최소화 — TODO, 하드코딩 색상 등은 포함하지 않음
  - 구현 파일: `.claude/hooks/pre-commit-check.sh`, `.claude/settings.json`
  - 의존성: bash, git, grep (jq 불필요 — Windows 호환)
  - 검증: 수동 테스트 통과 (디버그 코드 있으면 exit 2, 없으면 exit 0)

> **제외 근거**:
> - CSS 토큰 검사 → `/review-ui` 스킬이 예외 처리(SVG, color-mix, raw-ok 등)를 포함해 더 정확. 훅으로 만들면 오탐이 잦아져 무시하게 될 위험.
> - API 인증 검사 → 셸 스크립트로 Python 데코레이터 패턴을 정확히 잡기 어려움. code-reviewer 에이전트가 대체.

### Phase 2: 서브에이전트 — 역할 분리

> 메인 대화 컨텍스트를 보호하고, 분석/검증 작업을 독립 컨텍스트에서 수행한다.

- ⬜ **2-1. `codebase-researcher` 에이전트**
  - 역할: 구현 전 특정 서브시스템의 코드, 패턴, UX 지침을 전수 조사하여 구조화된 요약 반환
  - 도구: `Read, Glob, Grep` (읽기 전용)
  - 모델: `sonnet` (빠른 처리)
  - 출력: 파일 목록, 함수/API 구조, 기존 패턴, UX 지침 준수 상태
  - 효과: 메인 대화 컨텍스트 30~40% 절약
  - 프롬프트 설계 포인트:
    - 필수 참조 파일: `memory/theme-guide.md`, `css/tokens.css`, `css/components.css`, `CLAUDE.md`
    - 출력 형식: ① 파일 목록·구조 → ② 기존 패턴 요약 (이벤트 위임, 모달, 토스트 등) → ③ UX 지침 준수 현황 → ④ 구현 시 따라야 할 규칙
    - 조사 깊이: 함수 시그니처 + 호출 관계 + 상태 관리 패턴 (로직 내부까지는 불필요)
    - 분량 제한: 메인 대화에 반환할 요약은 50줄 이내

  **plan-advisor와의 역할 구분**:
  | | plan-advisor | codebase-researcher |
  |---|---|---|
  | 목적 | 계획서 vs 코드 **갭 분석** + 전략 자문 | 코드 **패턴·구조·지침** 조사 |
  | 출력 | 진행률, 리스크, 우선순위 권고 | 구현에 필요한 기술 요약 |
  | 시점 | 계획 수립 전, 방향 결정 시 | 구현 착수 직전 |
  | 예시 | "13번 계획서 상태 분석해줘" | "Compare 시스템 코드 패턴 조사해줘" |

- ⬜ **2-2. `code-reviewer` 에이전트**
  - 역할: 변경된 파일을 읽고 품질·보안·패턴 위반을 리포트
  - 도구: `Read, Glob, Grep` (읽기 전용 — 수정 권한 없음)
  - 모델: `sonnet`
  - 관점:
    - 보안: OWASP Top 10 (인젝션, 인증 누락, XSS 등)
    - 패턴 일관성: 기존 코드와 동일한 구조/네이밍 사용 여부
    - 디자인 토큰: tokens.css 변수 사용 여부, 다크모드 대응
    - 에러 핸들링: 적절한 예외 처리, 사용자 친화적 메시지
  - 출력: 우선순위별 이슈 (Critical → Warning → Suggestion)

  **기존 /review-ui 스킬과의 보완 관계**:
  | | /review-ui | code-reviewer |
  |---|---|---|
  | 범위 | CSS/HTML 테마 토큰 준수 | 로직, 보안, 패턴, 구조 전반 |
  | 깊이 | theme-guide.md 기준 정적 대조 | 코드 흐름 분석, 잠재 버그 탐지 |
  | 용도 | UI 변경 후 | 모든 코드 변경 후 |

### Phase 3: /review-ui 스킬 확장 — UX 품질 검사 보강

> 현재 /review-ui는 디자인 토큰 감사기(색상, 사이즈, radius 등 8개 항목)에 그침.
> 접근성, 상태 처리, 페이지 간 패턴 일관성은 검사하지 않음.
> 별도 에이전트 대신 기존 스킬을 확장하여 빈틈을 메운다.

- ⬜ **3-1. 접근성 점검 항목 추가**
  - 아이콘 버튼에 `aria-label` 존재 여부
  - 키보드 네비게이션 (tabindex, keydown 핸들러) 유무
  - 포커스 트랩 (모달 내 Tab 순환)
  - 시맨틱 HTML (button vs div[onclick])

- ⬜ **3-2. 상태 처리 패턴 점검 추가**
  - 빈 상태(empty state): 데이터 없을 때 안내 메시지 존재 여부
  - 로딩 상태: 스피너 또는 skeleton 표시 여부
  - 에러 상태: 사용자 친화적 메시지 (기술적 에러 노출 방지)
  - 패턴 통일: showToast vs alert, 모달 패턴(modal.css) 준수

- ⬜ **3-3. 페이지 간 일관성 점검 추가**
  - 공통 헤더(platform-header) 연동 여부
  - CSS 로드 순서 (CLAUDE.md 규칙 준수)
  - 모달/토스트/버튼 클래스 (components.css 활용 여부)
  - 다크모드 전환 시 깨지는 요소 없는지

> code-reviewer 에이전트(2-2)도 보안 관점에서 접근성을 체크하되,
> /review-ui는 UI/UX 관점에서 체크 — 겹치는 항목(aria-label 등)은 양쪽에서 잡히므로 누락 방지.

### Phase 4: 워크플로우 정립 (Phase 1~3 사용 경험 축적 후)

> Phase 1~3을 실제로 사용해보고, 어떤 조합이 자연스러운지 경험 기반으로 설계한다.
> 지금은 방향만 잡아두고, 구체적 체이닝은 실사용 후 재설계.

- ⬜ **4-1. 구현 전 워크플로우 정립**
  - 예상 흐름: codebase-researcher → 요약 확인 → 구현 계획 → 사용자 승인
  - 실사용 후 확정

- ⬜ **4-2. 구현 후 워크플로우 정립**
  - 예상 흐름: code-reviewer → /test-backend → /review-ui → 사용자 확인 → /git-commit
  - 실사용 후 확정

- ⬜ **4-3. CLAUDE.md에 워크플로우 섹션 추가**
  - 확정된 워크플로우를 문서화하여 대화 간 일관성 유지

## 참고

### 기존 스킬
- `/git-commit` — 커밋 메시지 규칙 준수
- `/review-ui` — 테마 토큰 준수 점검 → **Phase 3에서 UX 품질 검사로 확장 예정**
- `/test-backend` — API 엔드포인트 일괄 테스트
- `/update-docs` — 코드 변경 → 문서 자동 갱신

### 기존 에이전트
- `plan-advisor` — 계획서 대비 진행 상황 분석, 전략 자문

### 도구 선택 기준
- **스킬**: 메인 대화 맥락이 필요한 정형 단발 작업 (커밋, UI 리뷰)
- **에이전트**: 출력이 방대하거나 독립 컨텍스트가 유리한 작업 (코드 조사, 코드 리뷰)
- **훅**: 사용자 요청 없이 자동 실행, 셸 스크립트로 간결히 구현 가능한 검사
