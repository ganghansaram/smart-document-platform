## Phase 0 — 결과 해석 가이드 제작

현업 사용자가 "이 숫자가 무슨 뜻인가"를 즉시 이해할 수 있도록
**모드별 기준표 + 읽는 법** 설명자료를 제작한다.

### 0a. 유사도 검사 기준표

| 항목 | 내용 |
|------|------|
| 대상 | 유사도 모드 결과 화면 |
| 산출물 | 가이드 페이지 또는 인앱 도움말 |

**포함 내용:**

1. **점수 산출 공식 (간략판)**
   - 전체 문장 수 대비 매칭 문장 비율
   - 실질(일치+유사) 100% 반영, 의역(의역+번역) 50% 가중, 공통(상용구) 제외
   - 예시: 100문장 중 일치 20 + 유사 10 + 의역 6 → (30 + 6×0.5) / 100 = **33%**

2. **판정 기준표**

   | 구간 | 판정 | 색상 | 의미 | 조치 권고 |
   |------|------|------|------|-----------|
   | 0~30% | 양호 | 초록 | 독립 저작물 수준 | 특이사항 없음 |
   | 30~60% | 보통 | 노랑 | 부분 유사 확인 필요 | 일치/유사 항목 개별 검토 |
   | 60~100% | 주의 | 빨강 | 상당 부분 동일/유사 | 원본 대조·인용 표기 검토 |

3. **매칭 유형 해설**

   | 유형 | 라벨 | 뜻 | 판단 기준 |
   |------|------|----|-----------|
   | identical | 일치 | 단어가 동일 | 지문(fingerprint) 85% 이상 |
   | near_copy | 유사 | 일부 단어 변경 | 지문 40%↑ + 의미 85%↑ |
   | paraphrase | 의역 | 같은 내용을 다시 씀 | 지문 낮음 + 의미 88%↑ |
   | translation | 번역 | 다른 언어 동일 내용 | 교차 언어 의미 85%↑ |
   | low_sim | 참고 | 관련 가능성 | 의미 65~85% |
   | boilerplate | 공통 | 업계 표준 문구 | 상용구 DB 50%↑ 일치 |

4. **3단 분해 막대 읽는 법**
   - 실질(파랑) = 직접 유사, 의역(보라) = 간접 유사, 공통(회색) = 점수 제외

### 0b. 규칙 검증 기준표

**포함 내용:**

1. **점수 산출 공식 (간략판)**
   - Acrolinx 밀도 방식: 100단어당 가중 위반 밀도
   - 공식: `점수 = 100 × (1 - 밀도 / 5.0)`, 최소 0점
   - 가중치: 오류 ×5, 경고 ×2, 제안 ×1 (신뢰도 보정: 높음 1.0, 보통 0.7, 낮음 0.4)
   - 짧은 문서 보호: 200단어 미만은 200단어로 간주

2. **등급 기준표**

   | 점수 | 등급 | 색상 | 의미 |
   |------|------|------|------|
   | 90~100 | A | 초록 | 우수 — 규격 준수 양호 |
   | 80~89 | B | 연두 | 양호 — 경미한 개선 필요 |
   | 60~79 | C | 노랑 | 보통 — 주요 항목 수정 권장 |
   | 0~59 | D | 빨강 | 미달 — 재작성 또는 집중 수정 필요 |

3. **심각도 해설**

   | 심각도 | 라벨 | 색상 | 가중치 | 의미 |
   |--------|------|------|--------|------|
   | error | 오류 | 빨강 | ×5 | 규격 위반 — 반드시 수정 |
   | warning | 경고 | 노랑 | ×2 | 권고 위반 — 수정 권장 |
   | suggestion | 제안 | 파랑 | ×1 | 개선 여지 — 선택 수정 |

4. **카테고리 해설**

   | 카테고리 | 대상 | 대표 규칙 예시 |
   |----------|------|----------------|
   | 구조 | 번호 체계, 필수 섹션, 교차참조 | 절번호 연속성, 그림/표 캡션 |
   | 작성 | 문장 구조, 수동태, 경고문 | STE 문장길이, 접속사 |
   | 용어 | 금지어, 약어, 일관성 | 약어 첫 사용 정의 |
   | 가독성 | 문단 길이, 종속절 중첩 | 문단 6문장 이하 |

5. **점수 시뮬레이션 예시**

   | 시나리오 | 단어수 | 오류 | 경고 | 제안 | 밀도 | 점수 | 등급 |
   |----------|--------|------|------|------|------|------|------|
   | 우수 규격서 | 500 | 0 | 2 | 3 | 1.4 | 72 | C |
   | 일반 규격서 | 1000 | 2 | 5 | 8 | 2.8 | 44 | D |
   | 장문 양호 | 3000 | 3 | 4 | 10 | 1.2 | 76 | C |

   → **주의**: 시뮬레이션 결과를 보면, "일반적인 규격서"도 쉽게 D등급이 나올 수 있음.
   이것이 의도된 수준인지, 현업 기대치와 부합하는지 Phase 2에서 검증 필요.

### 0c. 문서 비교 해설

**포함 내용:**

1. **비교 모드에는 점수가 없음** — 왜?
   - 변경의 "좋고 나쁨"은 맥락에 따라 다르므로 자동 점수 부여 불가
   - 사용자가 개별 변경을 수락/거절로 판단

2. **변경 유형 해설**

   | 유형 | 라벨 | 색상 | 의미 |
   |------|------|------|------|
   | added | 추가 | 초록 | 신규 삽입된 내용 |
   | deleted | 삭제 | 빨강 | 제거된 내용 |
   | modified | 수정 | 노랑 | 변경된 내용 (단어 수준 표시) |

3. **AI 분류 태그 해설**

   | 태그 | 라벨 | 그룹 | 의미 |
   |------|------|------|------|
   | STRICTER | 강화 | 주의 필요 | 요구사항이 더 엄격해짐 |
   | MORE_LENIENT | 완화 | 주의 필요 | 요구사항이 느슨해짐 |
   | EXPANDED | 확대 | 참고 | 범위/내용이 확장됨 |
   | CLARIFICATION | 명확화 | 참고 | 기존 내용을 더 명확히 함 |
   | EDITORIAL | 편집 | 무시 가능 | 오타/서식 수정 |
   | RESTRUCTURED | 재구성 | 무시 가능 | 구조 변경, 내용 동일 |

4. **수락/거절 워크플로우**
   - 개별 판단 → 일괄 수락/거절 → 엑셀 내보내기

### 0d. 산출물 형태 결정

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A. 가이드 HTML 페이지 | 플랫폼 내 접근, 검색 가능 | 개발 필요 |
| B. 인앱 도움말 패널 | 맥락 적합, 즉시 참조 | 화면 복잡도 증가 |
| C. 엑셀/PDF 별도 자료 | 개발 없음, 인쇄 가능 | 시스템과 분리됨 |
| **D. A+B 혼합 (권장)** | 가이드 페이지 + 모드별 ? 버튼 | 가장 효과적 |

**권장**: D안 — 각 모드에 `?` 도움말 버튼으로 핵심 기준표 요약을 인앱 표시 +
상세 설명은 가이드 페이지로 연결.

## Phase 1 — 개발 전문가 관점 검토

코드 품질, 알고리즘 정확성, 엣지 케이스, 성능을 점검한다.

### 1a. 유사도 엔진 알고리즘 검증

| 점검 항목 | 검증 방법 | 판정 기준 |
|-----------|-----------|-----------|
| Paraphrase 분류 조건 | fp<0.15 AND sem≥0.88 조건으로 실제 의역 문장 검출률 측정 | Recall ≥ 70% |
| 분류 경계 사각지대 | fp=0.2~0.4, sem=0.80~0.87 구간 문장의 분류 결과 확인 | LOW_SIM 과다 없을 것 |
| 보일러플레이트 오탐 | 실제 규격서 10건에서 BP 필터 결과 수동 검토 | 실질 문장 제외 0건 |
| 한↔영 교차 유사도 | 동일 내용 한/영 문서 쌍으로 translation 검출률 측정 | Recall ≥ 60% |
| 장문 성능 | 1000문장 문서 처리 시간 측정 | < 60초 |

### 1b. 검증 점수 현실성 검증

| 점검 항목 | 검증 방법 | 판정 기준 |
|-----------|-----------|-----------|
| 점수 분포 | 실제 규격서 10건의 점수 분포 확인 | 50% 이상이 D등급이면 기준 과도 |
| 밀도 임계값 적정성 | DENSITY_THRESHOLD=5.0 vs 7.0 vs 10.0 비교 | 합격 기준 문서가 B 이상 |
| 단문 보호 | 100단어 문서에 warning 2건 → 점수 확인 | ≥ 60점 |
| 카테고리 독립성 | 한 카테고리 집중 위반 시 다른 카테고리 영향 없음 | 독립 확인 |

### 1c. 규칙 엔진 정확도

| 점검 항목 | 검증 방법 | 판정 기준 |
|-----------|-----------|-----------|
| 21종 규칙 개별 테스트 | 규칙별 양성/음성 샘플 2쌍씩 검증 | 42쌍 전수 통과 |
| 수동태 검출(STE-3.6) | 영문 기술문서 50문장 검증 | 오탐률 < 30% |
| 교차참조(38-XR) | Figure/Table 참조 문서로 검증 | 미검출 0건 |
| 절번호 연속성 | 의도적 누락/중복 삽입 → 검출 확인 | 100% 검출 |

### 1d. 엣지 케이스

| 시나리오 | 기대 동작 |
|----------|-----------|
| 빈 문서 업로드 | 에러 메시지, 크래시 없음 |
| 동일 문서 2개 비교 | 유사도 100%, 변경 0건 |
| 극단적 장문 (5000+ 문장) | 타임아웃 없이 결과 반환 |
| 한글 전용 문서 규칙 검증 | 영문 규칙 불적용, 크래시 없음 |
| 특수문자/수식 포함 문서 | 정상 파싱, 깨짐 없음 |

## Phase 2 — 웹 디자인 전문가 관점 검토

시각적 완성도, 색상 체계, 타이포그래피, 레이아웃 일관성을 점검한다.

### 2a. 색상 체계 검증

|-----------|-----------|-----------|
| 심각도 색상 구분 | 오류(빨)/경고(노)/제안(파) 3색 대비 | WCAG AA (4.5:1) |
| 유사도 판정 색상 | 양호(초)/보통(노)/주의(빨) 직관성 | 신호등 메타포 일치 |

## Phase 3 — UI/UX 전문가 관점 검토

사용자 흐름, 인지 부하, 학습 곡선, 오류 방지를 점검한다.

### 3a. 첫 사용자 경험 (OOBE)

| 점검 항목 | 검증 방법 | 판정 기준 |
|-----------|-----------|-----------|
| 허브 진입 시 안내 | 3개 모드 설명 충분한가 | 설명 없이도 선택 가능 |
| 파일 업로드 흐름 | 드래그 or 버튼 → 결과까지 | 3단계 이내 |
| 결과 화면 첫인상 | 점수/등급이 즉시 눈에 들어오는가 | 2초 내 핵심 파악 |
| 도움말 접근성 | `?` 버튼 발견 가능성 | 자연스럽게 발견 |

### 3b. 점수 해석 인지 부하

| 점검 항목 | 문제 상황 | 개선 방향 |
|-----------|-----------|-----------|
| 유사도 % vs 검증 점수 | 같은 72라도 의미 다름 | 라벨로 구분 ("유사율 72%" vs "품질 72점") |
| 3단 분해 막대 | 실질/의역/공통 용어 생소 | 툴팁 또는 범례 상시 표시 |
| 카테고리 점수 | 전체 점수와의 관계 불명확 | "이 카테고리가 전체에 N점 영향" 표시 |
| 밀도 개념 | 사용자에게 노출 안 됨 | 노출 불필요, 점수+등급으로 충분 |

### 3c. 오류 방지 및 복구

| 시나리오 | 현재 동작 | 개선 필요 여부 |
|----------|-----------|----------------|
| 일괄 수락 클릭 | 즉시 적용, 되돌리기 없음 | **확인 대화상자 필요** |
| 일괄 거절 클릭 | 즉시 적용 | **확인 대화상자 필요** |
| 모드 전환 중 미저장 | 경고 없음? 확인 필요 | 이탈 방지 가드 확인 |
| 잘못된 파일 형식 업로드 | 에러 메시지 | 허용 형식 사전 안내 |

### 3d. 정보 계층 구조

```
현재 구조 (검증 모드):
┌─────────────────────────────────────────────┐
│ [점수 링 72/100] [등급 C]                    │  ← 1차: 핵심 수치
│ 오류 2 | 경고 5 | 제안 8                      │  ← 2차: 요약
│ [심각도 막대]                                 │  ← 2차: 시각화
│ ├ 구조 [====] 85                             │  ← 3차: 카테고리 분해
│ ├ 작성 [===] 60                              │
│ ├ 용어 [====] 90                             │
│ └ 가독성 [==] 45                             │
│                                              │
│ ▼ 구조 (3건)                                 │  ← 4차: 개별 이슈
│   [오류] 절번호 3.2 누락                      │
│   [경고] 표 캡션 미비                         │
└─────────────────────────────────────────────┘

검증 포인트: 이 계층이 자연스럽게 읽히는가?
- 시선 흐름: 좌상단 → 우측 → 하단 순서 확인
- 색상 강도: 상위 정보일수록 시각적 무게감
```

### 3e. 네비게이션 흐름

| 흐름 | 단계 | 마찰 여부 확인 |
|------|------|----------------|
| 허브 → 유사도 → 결과 | 파일 2개 선택 → 분석 → 결과 | 파일 선택 UX |
| 허브 → 비교 → 수락/거절 | 파일 2개 → diff → 판단 → 내보내기 | 판단 완료 인지 |
| 허브 → 검증 → 수정 | 파일 1개 → 검증 → 이슈 클릭 → 위치 이동 | 이슈↔본문 왕복 |
| 결과 → 내보내기 | 결과 화면 → 엑셀 다운로드 | 내보내기 버튼 발견성 |
| 결과 → 허브 복귀 | 뒤로가기 or 허브 버튼 | 결과 유지 여부 |

---

## Phase 4 — 사용자 관점 실전 테스트

실제 업무 시나리오로 "의미 있는 결과가 나오는가"를 검증한다.

### 4a. 테스트 시나리오 설계

| # | 시나리오 | 입력 | 기대 결과 |
|---|----------|------|-----------|
| S1 | 동일 문서 유사도 | A.md vs A.md (복사본) | 유사도 ~100%, 주의 판정 |
| S2 | 완전 상이 문서 | A.md vs B.md (무관) | 유사도 ~0%, 양호 판정 |
| S3 | 부분 인용 문서 | A.md vs C.md (30% 인용) | 유사도 25~40%, 매칭 위치 정확 |
| S4 | 의역 문서 | A.md vs D.md (의역) | paraphrase 유형 검출 |
| S5 | 한↔영 번역 쌍 | A_ko.md vs A_en.md | translation 유형 검출 |
| S6 | 양호 규격서 검증 | good_spec.md | B등급 이상, 이슈 < 10건 |
| S7 | 불량 규격서 검증 | bad_spec.md | D등급, 주요 위반 검출 |
| S8 | 규격서 개정 비교 | spec_v1.md vs spec_v2.md | 변경점 정확 검출, AI 분류 |
| S9 | 단문 (100단어) 검증 | short.md | 과도한 감점 없음 (≥ 60점) |
| S10 | 장문 (3000단어) 검증 | long_spec.md | 60초 내 결과, 타임아웃 없음 |

### 4b. 테스트 데이터 준비

- `workbench/test-samples/verify/` 디렉토리에 테스트 파일 배치
- 각 시나리오별 입력 파일 + 기대 결과 문서화
- 가능하면 실제 업무 규격서 1~2건 포함 (민감정보 제거)

### 4c. Playwright 자동 테스트

각 시나리오를 Playwright MCP로 실행하여 스크린샷 캡처:
1. 파일 업로드 → 결과 화면 캡처
2. 결과 수치 확인 (점수, 등급, 매칭 수)
3. 이슈 클릭 → 본문 하이라이트 정상 동작
4. 내보내기 → 엑셀 파일 생성 확인
5. 다크모드 전환 → 결과 화면 캡처

## Phase 5 — 발견 사항 분류 및 수정

### 5a. 이슈 분류 체계

| 등급 | 기준 | 조치 |

| **P3 — 희망** | 고도화 (추가 기능, 미세 조정) | 백로그 이관 |

| # | 이슈 | 등급 | 관점 |
|---|------|------|------|

| I2 | 검증 점수 과도 가혹 (일반 문서 D등급) | P1 | 사용자 |

| I7 | AI 분류 배치 처리 느림 (200+ 변경) | P3 | 개발 |

### 5c. 수정 실행

- P0/P1 이슈: Phase 5에서 즉시 수정
- P2 이슈: 시간 허용 시 수정, 아니면 투입 후 패치
- P3 이슈: backlog.md 이관

### 6a. 인앱 도움말 구현

## 작업 순서 요약

```
Phase 0  기준표 설계 (본 계획서에 초안 완료)
   ↓
Phase 1  개발 관점 코드 검증 ─────┐
Phase 2  디자인 관점 시각 검증 ───┼─ 병렬 가능
Phase 3  UX 관점 흐름 검증 ──────┤
Phase 4  사용자 관점 실전 테스트 ─┘
   ↓
Phase 5  이슈 분류 및 수정 (P0→P1→P2 순)
   ↓
Phase 6  가이드 자료 탑재
```

**예상 규모**: Phase 0 초안은 본 문서에 포함.

Phase 5 수정은 발견 이슈에 따라 가변. Phase 6은 소규모.

## 의사결정 필요 사항

1. **가이드 자료 형태**: D안(인앱+가이드 페이지) 확정 여부
2. **검증 등급 기준**: 현재 A(90+)/B(80+)/C(60+)/D(-60) 유지 or 조정?

4. **Paraphrase 조건 완화**: fp<0.15 → fp<0.40 또는 조건 제거?
